## 4. P1（应修，6 项）

### P1-1 词条点击交互四态并存，§4.3② 行文自相矛盾（L2a 漏报）
- 位置：product-design.md S2-3（:41）、S3-2（:48）、§4.3②（:147）、§4.3③（:149）。
- 证据：S2-3"点击任一词条**切换**为该词的单词卡"；S3-2"难词条可点击朗读；**点击**词条切换单词卡"；§4.3②"点击朗读；**点击**词条切单词卡"（同一句内点击既朗读又切卡）；§4.3③"点击朗读，**长按/右键**切单词卡"。
- 影响：同一"词条"组件在句卡/段卡上的切卡手势三处三样，且 §4.3② 一句之内自相矛盾；实现者无所适从，测试无判定基准。
- 建议：统一为一种手势（推荐与 §4.3③ 对齐：点击=朗读，长按/右键=切卡），改 S2-3、S3-2、§4.3② 三处。

### P1-2 精读聚合请求只喂"逐批要点"，承诺的汇总生词表/术语表无数据来源（L2a 漏报）
- 位置：tech-design.md §4.3 精读模板（:222）vs product-design.md S4-2（:58-60）。
- 证据：tech"末批追加聚合请求：`{逐批要点}` → 输出逻辑解读 + 汇总生词表 top10–20 + 术语表"；product 生词表 Tab 承诺"逐项音标/文中义/**原文例句**/🔊"。聚合入参仅每批 2–3 条要点，不含各批难词表、更不含原文——模型无从给出"原文例句"，只能编造。
- 影响：M1 精读窗两个 Tab（生词表/术语表）的输出必然幻觉或缩水，属数据流级缺陷，T5"分批不截断"验收测不出来（截断≠内容来源）。
- 建议：聚合请求入参改为 `{逐批要点 + 逐批难词表 + 原文（或各批首段索引）}`，并在 §4.3 写明生词表"原文例句"取自输入侧原文（与取数契约①对齐）。

### P1-3 product §4.4 路由阈值行丢"无句中标点"条件，与 tech §4.1 不同源（P2-3 修复引入的相邻缺口）

### P1-4 screencapture 退出码语义：处置记录声称已登记校准，实际未落地；§3.3.1 把未验证语义写成事实
